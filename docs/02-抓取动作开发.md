# 抓取动作开发流程

动作不是一次成型的，是迭代出来的。最后一步的触觉数据会回到第一步。

## 五步循环

```
01 示教录制 → 02 参数整定 → 03 仿真预演 → 04 真机回放 → 05 触觉闭环
     ↑                                                        │
     └────────────────────────────────────────────────────────┘
```

| 步 | 做什么 | 产出 |
|---|---|---|
| 01 示教录制 | 人手带动 / 脚本示教，记录关节角序列 | 动作轨迹文件 |
| 02 参数整定 | 力度、速度、保持时间逐项标定 | 参数文件 |
| 03 仿真预演 | MuJoCo 校验限位与碰撞 | 预演记录 |
| 04 真机回放 | 一键回放，观察稳定性 | 回放录屏 |
| 05 触觉闭环 | 指尖数据回灌，修正力度与时序 | 参数修正 |

## 动作库

| 动作 | 适用物体 | 关键参数 | 状态 |
|---|---|---|---|
| 捏取 | 待补 | 力度阈值 / 指间角度 | 待补 |
| 掌握 | 待补 | 包络角度 / 力矩分配 | 待补 |
| 抓放 | 待补 | 保持时间 / 释放时机 | 待补 |
| 递物交接 | 待补 | 释放判定条件 | 待补 |

## 参数管理

每种动作一套参数文件，可复用、可对比、可回滚。不做"每次重新调一遍"——那样等于没有沉淀，下次遇到同样的物体还得从头来。

## 已知边界

仿真表现良好；真机受指尖传感器噪声影响存在波动。

我把它写在这里，是因为这个差距真实存在。触觉数据抖起来的时候，力度判定就会飘，抓取成功率跟着掉。接下来想做的是把触觉滤波和零偏标定做成上电自动流程，而不是每次手动调。
